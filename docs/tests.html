Manger / Testing

Run and extend the test suite

Isolated databases, simulated Telegram updates, and readable terminal results.

bash
composer test

The runner groups results by file, prints [OK] or [FAIL] for each named case, and finishes with totals and duration. Failures include details and produce a non-zero exit status for CI.

LocationResponsibility
tests/Bot/Command integration tests using simulated Telegram updates.
tests/Database/Migration, seed, constraint, and repository tests.
tests/Support/TestContext.phpShared setup, assertions, and a fake bot client.
tests/bootstrap.phpLoads test dependencies.
tests/run.phpDiscovers and runs *Test.php files recursively.

Each test gets a fresh in-memory SQLite database. Tests do not modify application data or send real Telegram messages.

To add a test, return an array of named callables from a *Test.php file. Each callable receives a Tests\Support\TestContext instance:

php
use Tests\Support\TestContext;

return [
    'Lists the default fruit group' => static function (TestContext $t): void {
        $t->command('/fgroup -I', 'fruits');
    },
];

What the suite checks

Tests cover command routing, operation flags, registration, catalog CRUD, food group lookup, consumption entry CRUD, ownership, daily uniqueness, rollback, local midnight, calendar boundaries, compact views, calorie goals, and autocomplete definitions.

Deterministic dates

TestContext accepts an optional clock closure. Use a fixed DateTimeImmutable when testing midnight, historical dates, or period boundaries. Each test context creates its own SQLite database and bot client.

Failures and CI

The GitHub Actions workflow in .github/workflows/tests.yml runs on pushes and pull requests, and can be started manually from the repository’s Actions tab. It tests PHP 8.2 and 8.5 with SQLite enabled, validates Composer configuration, installs locked dependencies, checks platform requirements, and runs composer test. No Telegram token or application database is required.

Run composer test in CI after installing dependencies and enabling PDO SQLite. The runner continues after a failed case, prints the exception message and location, and exits with status 1 if any test fails or no tests are found. A successful run exits with status 0.
