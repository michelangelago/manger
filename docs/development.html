Add new command handlers in app/bot/commands/, wire them in app/bot/commands.php, and update app/bot/menu.php and /help. Keep queries in repositories and reusable display formatting in app/bot/support/.

Request lifecycle

  1. app/bot/bot.php loads the bootstrap module, synchronizes the menu, and starts polling.
  2. bootstrap.php loads Composer dependencies and .env, creates the Nutgram client, connects SQLite, and constructs repositories.
  3. commands.php registers handlers and injects repositories, timezone, and clock dependencies.
  4. Handlers parse input, identify the sender when personal data is involved, and call repositories.
  5. View helpers format results before the bot sends a Telegram reply.

Adding a feature

  1. Add a numbered migration if the schema must change. Keep applied migrations intact.
  2. Add persistence methods to the appropriate repository; use parameterized queries and scope personal records by user.
  3. Add a command handler and register its bare and argument forms in app/bot/commands.php.
  4. Keep reusable parsing and presentation logic in app/bot/support/.
  5. Update /help, autocomplete definitions in app/bot/menu.php, and the documentation.
  6. Add tests and run composer test before starting the bot again.

Boundaries and current behavior

The catalog is shared between users. Personal logs, consumption, and goals use the sender's Telegram ID to find their application user. Commands that access personal records require /start registration.

EatCommand delegates to DailyFoodCommand so the shortcut shares consumption validation and persistence. Daily log creation and the consumption insert are atomic.

Daily summaries calculate calories from the current food catalog values. Editing a food's energy can therefore change totals for earlier consumption. Goal settings have no historical versions and are compared only against today's daily view.

The public/index.php endpoint is a plain environment status page. It does not serve the bot or this documentation. Open the HTML documentation directly, or serve docs/ separately.
