Known verification gaps

  • No live Telegram end-to-end suite, load test, production uptime measurement, restore drill, or scheduled backup test is present.
  • Daily uniqueness is checked by constraints and repeat calls; tests do not simulate simultaneous production polling processes.
  • Existing schema migration functions are tested; there is no full subprocess migration-runner lifecycle test.
  • Not all observed limitations have dedicated automated regression tests. A source inspection observation is labeled as such on the limitations page.

Keeping this specification accurate

  • When behavior changes, update its FR and BR entries, related diagrams, command guide, and tests.
  • Add schema changes as a new migration and refresh the dictionary against an isolated migrated database.
  • Keep SVG renderings and their editable Mermaid sources consistent. SVG files are the offline display; Mermaid sources are not runtime dependencies.
  • Run composer test and validate documentation links before claiming that a new implementation is verified.
